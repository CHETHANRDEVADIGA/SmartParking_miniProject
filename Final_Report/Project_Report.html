ABSTRACT

Urban vehicular parking management has become a critical operational domain requiring robust software architectures to handle real-time slot allocation, dynamic hourly pricing tariffs, QR ticketing, advance reservations, and bay occupancy mapping. Because parking systems govern direct commercial transactions and physical bay access, software defects can trigger revenue leakage and facility paralysis.

This project demonstrates an exhaustive, industrial-standard software testing and quality assurance lifecycle applied to a full-stack Smart Parking Management System (React 18 frontend, Express.js v5 backend, and SQLite 3 relational database). Both Black-Box and White-Box testing paradigms were systematically applied:

  • Black-Box Testing: We formulated 15 comprehensive functional test scenarios. Equivalence Class Partitioning (ECP) was applied across user authentication, vehicle plate identification, role-based authorization, and booking timestamps. Boundary Value Analysis (BVA) verified duration rounding rules (0m, 1m, 59m, 60m, 61m) and parking bay capacity limits.
  • Cypress Automation Testing: A complete end-to-end automation test suite was engineered in Cypress (v13.17.0) executing headlessly against Google Chrome and Electron. All 15 functional test cases achieved a 100% pass rate with high-resolution screenshot evidence.
  • White-Box Structural Analysis: We modeled Control Flow Graphs (CFG) for core transactional modules (assignSlot, processExit, and bookTx), calculated McCabe's Cyclomatic Complexity (V(G) = 4 to 6), and mapped all linearly independent execution paths for full branch coverage.
  • Empirical Defect Discovery: Testing identified and documented a critical SQLite identifier quoting defect in the live backend, providing actionable code remediation.

CHAPTER 1: INTRODUCTION & PROBLEM STATEMENT

1.1 Project Background

With rapid urbanization, manual vehicle parking management is increasingly untenable. Drivers face long queuing times, parking attendants struggle with manual paper ticketing, and facility managers experience revenue discrepancies. Modern Smart Parking Systems automate these workflows by auto-assigning closest available bays, calculating fees dynamically based on vehicle type and duration, generating digital QR receipts, and providing real-time dashboard analytics.

1.2 Problem Statement

Because parking software interacts concurrently with database records and executes financial computations, manual testing is insufficient. Subtle edge-case bugs—such as charging drivers 2 hours for a 59-minute park, race conditions permitting double-booking, or unhandled SQL syntax exceptions—cause severe operational disruption. Rigorous Black-Box and White-Box automated testing is essential to ensure operational integrity.

CHAPTER 5: TEST DESIGN TECHNIQUES (ECP & BVA)

5.1 Equivalence Class Partitioning (ECP)

Input domains were divided into valid and invalid equivalence partitions:

  • Email Address: Valid = registered RFC email (sweet@gmail.com); Invalid = empty, malformed, or unregistered email.
  • Password: Valid = matching bcrypt hash (queen); Invalid = empty or wrong password.
  • Role & Secret Key: Valid = 'User' (no key), 'Admin' (key = 'admin123'); Invalid = 'Admin' with incorrect key.
  • Vehicle Category: Valid = 'Car', 'Bike'; Invalid = any other string ('Truck', 'Bus').

CHAPTER 7: DEFECT ANALYSIS & CONCLUSION

7.1 Identified Defects

DEF-01: SQLite Identifier Quoting Syntax Error (Severity: Critical)
In backend/routes/parking.js line 26, the SQL statement uses double quotes around "Available". In SQLite, double quotes indicate column identifiers, throwing no such column: Available. Fix: Use single quotes 'Available'.
DEF-02: Missing Schema Constraint Allows Negative Tariffs (Severity: Medium)
The rates table lacks CHECK(hourly_rate > 0), allowing negative hourly rates that corrupt billing calculations. Fix: Add non-negative constraint to table and API handler.
